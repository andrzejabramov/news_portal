## 1. 📧 Модуль почтовых уведомлений

### 1.1. Общая архитектура
*   **Брокер задач:** Redis (асинхронная очередь)
*   **Библиотека:** Celery 5.4.0 для фоновых и периодических задач
*   **Бэкенд:** Настраивается через переменные окружения (`.env`). Для разработки — консольный (`console`), для продакшна — SMTP (Яндекс).
*   **Шаблоны писем:** Находятся в `templates/emails/`. Есть HTML и текстовая версии для каждого типа писем.

### 1.2. Функционал

#### 1.2.1. Приветственное письмо
При регистрации нового пользователя ему уходит приветственное письмо на указанный им email:
![Приветственное письмо](/img/email_reg.png)

*   **Триггер:** Сигнал `post_save` на модели `User` → постановка задачи в Celery (`send_welcome_email.delay(user_id)`)
*   **Получатель:** Email, указанный пользователем при регистрации.
*   **Содержание:**  
    *   Персонализированное приветствие с именем пользователя.
    *   Список ключевых возможностей портала.
    *   Прямая ссылка на каталог новостей (`/news/`).
*   **Обработка ошибок:** Логирование ошибок, автоматические повторные попытки (retry) при сбоях SMTP.

#### 1.2.2. Мгновенное уведомление о новой публикации
При подписке авторизованного пользователя на категорию публикации:
![Подписка на категорию публикации](/img/subscribe_new.png)

Или из страницы списка всех публикаций:
![Подписка на категорию публикации](/img/subscribe_news.png)

При создании публикации подписанту отправляется уведомление на email:
![Уведомление о публикации](/img/email_new.png)

*   **Триггеры:**  
    1.  **Создание поста:** Сигнал `post_save` с `created=True` → `send_new_post_notifications.delay(post_id)`
    2.  **Добавление категории:** Сигнал `m2m_changed` для связи `Post.categories.through` → `send_new_post_notifications.delay(post_id)` (с защитой от спама)
*   **Получатели:** Все пользователи с **активной** подпиской (`is_active=True`) на любую из категорий нового поста.
*   **Содержание письма:**  
    *   Заголовок публикации.
    *   Краткое содержание (первые 124 символа).
    *   Ссылка на полный текст статьи.
    *   Ссылка для отписки от данной категории.

#### 1.2.3. Еженедельный дайджест
![Еженедельный дайджест](/img/email_digest.png)

В текущей реализации используется **Celery Beat** для планирования задач.

**Файл конфигурации:** `pr_settings/celery.py`
```python
app.conf.beat_schedule = {
    'weekly-digest-monday-9am': {
        'task': 'news.tasks.send_weekly_digest',
        'schedule': crontab(hour=9, minute=0, day_of_week=1),  # Понедельник 9:00
        'args': (),
    },
}
```
Запуск Celery Beat:
````
celery -A pr_settings beat -l info --scheduler django_celery_beat.schedulers:DatabaseScheduler
````
Периодичность: Каждый понедельник в 09:00 (настраивается в celery.py или через админку)

Получатели: Все пользователи, имеющие хотя бы одну активную подписку.

Механизм работы:

Собираются все посты, опубликованные за последние 7 дней.
Посты группируются по категориям.
Для каждого пользователя формируется персонализированное письмо.
Содержание письма:

Приветствие.

Список новых постов по категориям подписки.

Для каждого поста: заголовок, автор, дата, краткое содержание и ссылка.

Команда для тестирования: send_weekly_digest.delay() в Django shell

6. 📊 Сравнение: APScheduler vs Celery+Redis


Критерий	APScheduler (было)	Celery + Redis (стало)
Тип	Встроенный планировщик	Отдельный процесс + очередь
Производительность	Блокирует при долгих задачах	Полностью асинхронный
Масштабирование	Один процесс	Множество worker'ов
Отказоустойчивость	Нет повторных попыток	Автоматические retry
Мониторинг	Только логи	Flower, логи, админка
Гибкость	Ограниченный cron	crontab, интервалы, кастомные расписания
Скорость ответа	Ждёт отправки писем	Мгновенный ответ пользователю
